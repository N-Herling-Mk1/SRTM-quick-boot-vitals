GLOSSARY

what the numbers on this page actually mean

The question this page answers

A value on a screen carries no evidence of its own freshness. A frozen board and a healthy one both render as numbers. Everything here exists to tell those two apart.

t_poll

Seconds since Telegraf last wrote anything to InfluxDB. Catches a dead pipeline — container stopped, VPN dropped, collector crashed. Blind to a frozen board: Telegraf writes on a 5 second schedule whether or not the value moved, so a stuck board still produces a healthy-looking t_poll forever. This is why one clock is not enough.

t_change (tΔ)

Seconds since a channel's value last actually differed. Catches the frozen board, the wedged OPC UA server, the stalled IPMC. Derived from value transitions, not timestamps — so it works correctly even though Telegraf polls rather than subscribes.

t_wincc

Not yet built (mk_1). Would measure how long since the WinCC datapoint for the same channel changed. t_change small + t_wincc large = the panel is stale over live data, which is the bug this project was started to catch.

Canary counters

Six monotonic counters — FF11/12/13_uptime, IPMC_seq, IPMC_rawtime, IPMC_time. They only ever count upward, so one that stops advancing is unambiguously frozen. Most channels can't do this job: a voltage rail may sit flat and be perfectly healthy. The canaries have no benign reading, which is what makes them the liveness oracle.

Cadence map

One cell per channel. Colour is t_change ÷ that channel's own baseline interval — a ratio, not a fixed number of seconds. A 5 second voltage rail and a 15 minute uptime counter are both green when healthy. Baselines come from tools/build_baseline.py, measured against real history.

  • green — changing on schedule
  • yellow — lagging its normal rhythm
  • orange — well overdue
  • red — effectively stopped
  • static — identity string, never expected to change
  • no base — no baseline yet; run the baseline tool

Channel classes

  • COUNTER — monotonic. The canaries. Unambiguous when stopped.
  • ANALOG — continuous sensor. Should jitter. Flat is suspicious but not proof.
  • DISCRETE — flag or bitfield. Flat for hours is correct.
  • STATIC — identity string. Never changes by design.

μ and σ

Rolling mean and standard deviation over the window. σ is a second liveness sensor: a frozen analog channel has σ exactly zero. It is displayed but never alarmed, because σ=0 is equally consistent with a genuinely quiet rail, or one whose ADC step is coarse relative to its real noise. Alarming on it needs a per-channel healthy baseline first.

μ answers a different question — drift, not liveness. A board slowly heating shows in μ, not σ.

Read-only

Every query here is a read against Prof. Cheu's production TIG stack. Nothing is written, no container is restarted, no config is edited.
